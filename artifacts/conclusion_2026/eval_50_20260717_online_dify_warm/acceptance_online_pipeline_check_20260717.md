`generate_release_risk_note.py`、`validate_eval_dashboard_gate.py`、

本轮改为手动执行等效步骤（见下）。这是一个应记录并在后续迭代中修复或删除的工具链缺口，
与知识库/RAG回答质量无关。

## 重要发现 1：Dify 容器"刚启动即接受请求"存在可靠性隐患

第一次运行中的6次失败全部发生在 Dify 容器组刚用
`docker compose up -d` 拉起、`nginx` 已能响应基础健康检查但 `weaviate`/`sandbox`/
`redis` 等依赖服务尚未完全就绪的窗口期内，请求耗时21～87秒后才超时回退（未产生
可读的 `error` 字段，`upstream_ms=0`）。约1小时后重跑，同样50题零失败，证实这是
**容器冷启动预热期问题，不是持续性的在线链路可靠性缺陷**。

**建议**：正式验收/评审前的在线主链路复测，应在 `docker compose up -d` 后增加一个
"真实对话往返"级别的预热探测（而不仅是 nginx 健康检查通过），确认所有依赖服务
（尤其 weaviate 向量库、sandbox 代码执行沙箱）都已就绪后再开始计分，避免把冷启动
瞬时故障误判为链路缺陷。

## 重要发现 2：真实 DeepSeek 生成内容质量总体良好，但比人工调优的本地降级内容更"跳变"

50题中有21题（EV-001/002/003/004/006/007/011/012/015/020/021/024/025/031/033/
038/039/043/044/045/046）走了真实在线 `dify-workflow` 路径（其余29题走
`local-fast-path`/`rule-engine`，内容与不含在线Dify时的纯本地降级链路运行逐字一致，
已用脚本对比确认无差异，故沿用此前 `../eval_50_20260717_acceptance_check/` 轮次
对应评分）。

对这21题的真实 DeepSeek 回答逐条复核：**未发现任何危险性错误或方向性错误**，多数
回答内容全面、结构清晰、覆盖预期关键词完整（15/21 = 3分）。但有 **6/21 题存在可用但
不完整的缺口（2分）**：

| 题号 | 问题 | 缺口说明 |
|---|---|---|
| EV-001 | 浓硫酸稀释步骤 | 未提及通风柜要求 |
| EV-003 | 配制氢氧化钠溶液 | **回答在54.9秒长耗时后于句中被截断**（"...容易吸收空气中的水分和二氧化"），内容不完整，疑似流式/长度截断的技术问题，建议排查 |
| EV-007 | 过氧化氢能否与有机溶剂混合 | 该题为判断型问题，回答给出学术化的"不能笼统说绝对不能混合"结论，未给出面向普通实验室用户的明确"禁止"红线指引，存在被误读为"可自行尝试"的风险 |
| EV-024 | 水银温度计破碎处理 | 未提及硫粉中和这一预期处置技术 |
| EV-025 | 烘箱烘干玻璃仪器注意事项 | 遗漏该题风险最高的两点：残留可燃溶剂的火灾风险、禁止无人值守烘烤 |
| EV-031 | 真空泵使用安全事项 | 给出的是通用泵类设备安全，未覆盖真空泵特有的核心危害——内爆风险、冷阱、防护网/防爆屏蔽 |

以上6题均**不存在"给出错误处置方法"的危险性问题**，只是相对预期关键词清单而言不够
完整，或（EV-007）措辞不够斩钉截铁。这与本地降级链路（经过本会话及此前多轮人工调优的
KB内容）相比，说明**大模型自由生成的回答天然存在"覆盖面随机波动"的特点**，不像人工
调优过的结构化模板那样能保证每次都命中同一组关键安全点——这是在线RAG路径的固有特征，
建议后续可以考虑在 Dify Workflow 的提示词中显式要求模型对标准关键安全点（如设备特有
危害、判断型问题需给出明确结论）做检查清单式覆盖，而非仅做开放式问答。
