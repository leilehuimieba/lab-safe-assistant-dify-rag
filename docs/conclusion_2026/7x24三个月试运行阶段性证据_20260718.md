## 1. 证据口径

本文件只汇总仓库中已有代码、脚本、运行快照和历史文档证据，不倒填、不删除失败记录、不把间歇性采样包装成全程无故障。

可用于结题材料的稳妥口径是：

> 项目自 2026-05-22 起建立 7x24 / 三个月试运行监测机制，开始对本地 Demo、Dify 上游、知识库加载和性能指标进行留痕。现有证据已覆盖 2026-05、2026-06、2026-07 三个自然月份的阶段性运行记录，并包含故障样本、恢复动作和最新可用状态。由于截至 2026-07-18 仍未满完整三个月，本阶段材料作为“三个月试运行的过程性证据”，后续继续累积至完整周期后形成最终报告。

不建议使用的口径是：

- “系统已完成三个月 7x24 无中断运行”；
- “三个月内全程可用率 100%”；
- “现有快照等同于完整 15 分钟粒度三个月采样”；
- “失败快照可以剔除后再计算可用率”；
- “5 月至今 Dify 从未中断”。

## 6. 故障样本与解释

现有快照中包含故障记录，主要类型包括：

- 本地 Demo `8091` 未运行，导致 `/health` 连接失败；
- Dify 上游不可达或返回异常；
- Docker Desktop 未启动时，Dify 8081 无法访问；
- 2026-07-16 曾出现 `dify_http_401`，说明 App Key 或 Dify 鉴权状态需要复核；
- 2026-07-17 至 2026-07-18 曾出现若干 `502` 或连接失败快照，已在 2026-07-18 恢复记录中闭环。

这些故障样本应作为试运行过程中的问题记录保留。它们可以支撑“系统具备监测、发现问题和恢复的闭环”，但不能支撑“全程无故障”的结论。

## 7. 后续执行流程

为把现有 5 月起始证据继续沉淀为完整三个月试运行材料，建议继续执行：

1. 每日固定运行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/run_runtime_check_once.ps1 `
  -BaseUrl http://127.0.0.1:8091 `
  -ReportLabel latest
```

2. 每周固定生成周报：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/build_weekly_runtime_report.ps1 `
  -BaseUrl http://127.0.0.1:8091 `
  -IsoWeek 2026Wxx
```

3. 如需注册每日任务：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/register_daily_runtime_check.ps1 `
  -RunTime 08:30 `
  -BaseUrl http://127.0.0.1:8091 `
  -ReportLabel latest
```

4. 每周人工补充：

| 字段 | 填写要求 |
|---|---|
| 本周快照数 | 从周报或 `runtime_latest_summary.md` 读取 |
| `/health` 正常率 | 保留脚本统计值 |
| Dify 可达率 | 保留脚本统计值 |
| 故障时间段 | 按快照失败时间填写 |
| 故障原因 | 如 Docker 未启动、Demo 未启动、Dify 上游异常等 |
| 处理动作 | 写明恢复脚本、重启动作和复核结果 |
| 是否影响演示 | 如影响，写明影响范围 |
