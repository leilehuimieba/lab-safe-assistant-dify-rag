# 远程主监测环境接入记录（2026-07-23）

本文档记录 2026-07-23 当天发现并接入一台已独立运行约 3 个月的云服务器作为
7x24 主监测环境的完整过程。本文档是对 `7x24三个月试运行阶段性证据_20260723.md`
的补充说明，不修改、不覆盖此前任何证据文件。

## 1. 背景：发现一台已长期运行的服务器

在排查本地 7x24 监测缺口时，用户提供了其笔记中记录的一台腾讯云服务器
（Ubuntu 24.04，公网 IP 记录于用户私密笔记中，本文档不重复记录）信息。经核实：

- 该服务器上部署的是**同一个项目**（AGENTS.md、web_demo 代码结构、知识库文件等均一致）。
- 通过 `systemd`（`labsafe.service`）管理，端口 8088，已运行约 3 个月。
- 服务器上的代码停留在 2026-05-27（落后本地约 2 个月），且**不是 git 仓库**。

## 2. 发现的问题与修复

### 2.1 端口占用导致的伪·崩溃循环

`systemctl status labsafe.service` 显示重启计数已达 **573000+ 次**。排查
`journalctl` 发现真实原因：一个孤立的、非 systemd 管理的 python 进程
（pid 1760102，已运行 56 天 20 小时）已经占用了 8088 端口并且**正常提供服务**，
导致 systemd 每次重启都因 `[Errno 98] address already in use` 立即退出，
`RestartSec=5` 触发无限重试。

**这不是一次真实的服务中断** —— 该端口上的旧进程本身一直健康运行，只是
systemd 管理层面处于持续失败状态。

修复：定位孤立进程 pid，`kill` 后等待约 8 秒，systemd 下一次计划重启成功绑定端口，
`systemctl status` 确认 `Active: active (running)`，新的 Main PID 由 systemd 正常管理。

### 2.2 代码重新部署

将本地最新代码（不含密钥、`.venv`、本地专属大文件）通过 tar 传输 + `rsync -a`
（不带 `--delete`，保留远程专属的 `.env.web_demo`/`.env.dify_rag`/`.venv`）合并进
远程工作目录，安装两个新增依赖后重启服务。部署前完整备份原目录。

部署后验证：`/health` 返回 `status:"ok"`, `kb_loaded:3009`, `dify_reachable:true`
（首次探测因冷启动短暂 `degraded`，第二次即恢复正常）。

### 2.3 快照文件污染

远程部署完成后发现 `artifacts/runtime/health_snapshots.csv`/`.jsonl` 中混入了
**11 行本地机器（Windows，2026-05-22）的历史快照数据** —— 由于
`artifacts/runtime/` 在本地是 git 追踪的例外目录，被 tar 打包时一并带到了远程。
同时 `artifacts/local-dify-rag/runtime.json`（记录本地开发进程 PID/URL/python
路径）也被一并复制，导致远程新产生的快照里出现了 `D:\Grammar\python\python.exe`
这样明显错误的元数据。

处理方式：**先在远程完整备份**当前文件（`artifacts/runtime/_backup_before_dedup_20260723/`），
再只保留 `base_url` 属于该服务器自身（`127.0.0.1:8088`）的行，并删除失效的本地
`runtime.json`（不做任何伪造替代，相关字段此后如实留空）。此过程未删除、
未修改本地仓库中的任何历史记录。

## 3. 建立的定时采集与回传机制

- 远程 crontab 新增：每 15 分钟运行一次
  `scripts/record_runtime_snapshot.py --base-url http://127.0.0.1:8088`，
  快照写入远程自身的 `artifacts/runtime/health_snapshots.csv`/`.jsonl`。
  （同时移除了一条早已失效、指向不存在目录的旧 cron 任务
  `lab-safe-go-live-bundle`。）
- 新增 `scripts/merge_runtime_snapshots.py`：按 `(captured_at, base_url)`
  去重，将远程快照合并进本地 git 仓库的快照文件，只新增、不覆盖、不删除。
- 新增 `scripts/pull_remote_runtime_snapshots.ps1`：scp 拉取远程快照 +
  调用合并脚本的一键编排。远程连接信息（服务器 IP、SSH key 路径）存放在
  `scripts/.remote_runtime.local.json`（已加入 `.gitignore`，不入库），
  仓库中只保留不含真实值的 `.example` 模板。

首次拉取合并验证：新增 2 条真实远程快照（`2026-07-23T14:47:55`、
`2026-07-23T14:52:37`），均为 `health_ok=true`、`dify_reachable=true`。
合并后本地 `health_snapshots.csv` 总行数由 79 增至 **82 行**，覆盖天数仍为
**26/63 天**（新增快照落在已有数据的 2026-07-23 当天）。
