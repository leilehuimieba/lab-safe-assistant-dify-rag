# 专家审查与产品体验改进记录（2026-07-25）

## 1. 总体判断

该项目已经具备“大创可演示原型”的主要链路：本地知识检索、安全规则、Dify 上游、结构化兜底、引用卡片、反馈、运行监控与知识库态势页。当前最大短板不在页面是否“像 AI 产品”，而在以下三点：

1. **高风险问答的语义正确性**：一次真实交互复测发现“乙醚洒漏且人员头晕”曾被误判为明火规则，并引用针刺伤内容。这类错配会直接影响答辩可信度，本轮已优先修复。
2. **来源可核验与本地留存覆盖不足**：字段完整不等于链接都能打开，也不等于已有原件备份。当前只能如实表述为“已完成全量链接审计，部分来源有本地证据，PDF 原件仍在补档”。
3. **人工评审覆盖偏低**：3009 条中仅 38 条状态为 `reviewed`；应建立分层抽审和签名留痕，而不是继续单纯扩充条目数量。

## 2. 本轮发现并修复的关键问题

### P0：真实化学品事故被错误规则/知识命中

- 复现问题：输入“乙醚洒在实验台上并有人感到头晕，应该怎么办？”。
- 修复前：命中 `R-002`，首条依据为针刺伤/血源暴露，回答出现 HIV PEP 等无关内容。
- 根因：
  - 规则选择只按严重度/命中长度排序，未区分“正在发生的事故”与“禁止性问法”；
  - `R-015` 泄漏规则缺少“洒在/洒出/泼洒/溢出”等自然语言表达；
  - 检索缺少“乙醚”和“泄漏”查询锚点。
- 修复：
  - 为规则选择加入“应急意图优先于一般禁止规则”的上下文优先级；
  - 扩展乙醚与化学品泄漏检索锚点；
  - 补齐 `R-008/R-016~R-022` 的结构化应急模板；
  - 收紧恶意爆炸关键词，避免把真实爆炸事故误判为恶意请求；
  - 修正激光眼暴露、低温冻伤、辐射事件中的不严谨固定处置表述。
- 修复后实测：同一问题稳定命中 `R-015`，首批引用切换为危险化学品泄漏/HAZWOPER、`Prudent Practices in the Laboratory` 等相关来源，43ms 返回本地规则答案，不再出现针刺伤/HIV 内容。

### P1：移动端没有完整导航

- 修复前：390×844 视口下左侧栏直接隐藏，用户无法新建对话、进入知识库态势、重用历史问题或退出登录。
- 修复后：顶部增加移动导航入口，抽屉包含与桌面侧栏一致的关键操作，并支持点击遮罩、关闭按钮和 `Escape` 关闭。

### P1：中等宽度布局溢出

- 修复前：三栏布局直到 1023px 才隐藏右侧元数据栏，约 1100px 宽时中间回答区域明显受挤压。
- 修复后：使用 `minmax(0, 1fr)` 和 `min-height: 0` 修正 Grid/Flex 收缩边界；在 1180px 以下隐藏右栏，移动端压缩头部、输入区和页脚。

### P1：页面存在无法证明的安全文案

- 将页脚“已加密 · 已脱敏”改为“本地演示环境”。当前本地 HTTP 演示不能以该文案对外承诺端到端加密。
- 演示密码由长期 `localStorage` 改为标签页级 `sessionStorage`，并自动迁移旧会话，降低浏览器长期留存风险。

### P2：引用透明度

- 引用卡片增加来源域名与 `PDF/网页` 类型标识，用户在打开外链前即可判断来源去向和载体。

本轮全量审计口径：

| 指标 | 结果 |
|---|---:|

| 被站点/反爬策略阻断 | 333 |

必须使用以下严谨口径：

- 333 个 `blocked_or_forbidden` **不能直接称为死链**；它们只代表审计脚本被 403/反爬/验证页阻断，需要浏览器抽样或官方镜像复核。
- 31 个 `network_error` 当前不能计入“已核验可访问”。
- 本地 Markdown 或官方镜像属于“可追溯证据”，不等同于原始 URL 的 PDF 原件。
- 当前不能回答“每个 PDF 都有本地备份”；准确答案是 **111/151 个 PDF 来源有本地 PDF 原件，仍缺 40 个（原因逐条记录，非死链）**。

## 4. 产品体验参考与落地取舍

本轮参考的不是纯视觉风格，而是优秀知识型 AI 产品中可解释、可继续追问、可定位来源的交互：

- ChatGPT Search：回答内展示引用，并提供来源面板；
  - https://help.openai.com/en/articles/9237897-chatgpt-
- Google NotebookLM：回答基于用户选择的来源，点击引用可回到具体来源上下文；
  - https://support.google.com/notebooklm/answer/16179559?hl=en
- Perplexity：每次回答强调来源透明度，并保留连续追问上下文；
  - https://www.perplexity.ai/help-center/en/articles/10352895-how-does-perplexity-work
- Dify Chat API：支持生成下一步建议问题；
  - https://docs.dify.ai/api-reference/chats/get-next-suggested-questions

适合本项目的下一批交互（按价值排序）：

1. **引用定位与证据状态**：在引用卡片显示“本轮实测可访问/站点阻断/有本地备份”状态，并允许打开本地归档。
2. **应急答案置顶折叠**：首屏只保留“立即做什么/不要做什么/何时升级”，详细依据折叠，减少事故现场阅读负担。
3. **建议追问**：根据当前回答给出 2~3 个下一步问题，例如“泄漏量多大算需要撤离”“SDS 在哪里找”；Dify 不可用时用本地规则生成。
4. **回答复制与导出**：复制答案时附带引用 ID、生成时间和“仅供参考”声明，便于值班记录和答辩演示。
5. **来源管理工作台**：按 `network_error/blocked/missing_pdf/unreviewed` 筛选并分派复核，而不是只展示总数。

## 5. 仍需完成的验收工作

### 第一优先级：数据治理

1. 继续补齐影响片段数最多的剩余 40 个 PDF 原件（多数需换网络环境/校园网/VPN 绕过站点 CDN/WAF 拦截），并记录 SHA-256、获取时间、最终 URL、文件大小与许可证/公开性。
2. 对 31 个网络错误逐个浏览器复核，若原链接失效则换用同机构的新链接或官方镜像，不能用非权威转载替代。
3. 将 333 个站点阻断来源按影响片段数分层抽检，保存人工核验时间和证据截图/归档。
4. 把 `reviewed` 从 38 条提升到可解释的分层样本：高风险/应急类 100% 人审，中风险按来源和主题分层抽样，低风险随机抽样。

### 第二优先级：运行链路

1. 当前本地演示环境未配置 `DIFY_APP_API_KEY`，因此实际运行的是“规则 + 本地检索兜底”，不是 Dify 主链路；答辩前必须用服务器端环境变量接通并记录 SSE 首字节。
2. 对 Dify 可用、超时、返回空、流中断、Key 缺失五种状态分别做验收截图和响应时间记录。
3. 建立 20~30 条“多意图冲突”回归集（如泄漏+头晕、爆炸事故+如何处置、激光+化学品同时入眼），防止规则严重度再次压过真实事故意图。

### 第三优先级：前端与安全

1. `react-router` 的安全公告中仍有 RSC/SSR/Actions 相关项；本项目是纯客户端 HashRouter，不使用这些功能，但应在依赖评审中记录“当前不可达”，并在兼容版本可用时升级。
2. 演示密码仍属于共享口令，不是正式用户身份系统。若进入真实试运行，应切换到学校统一认证或至少服务端会话，不在前端持有明文共享口令。
3. 增加无障碍焦点圈、抽屉焦点锁定、屏幕阅读器实时状态提示和键盘全流程测试。
