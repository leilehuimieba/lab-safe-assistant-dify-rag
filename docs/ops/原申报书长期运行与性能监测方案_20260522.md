## 3. 记录频率建议

### 恢复 Dify 前

1. 每日一次本地 `/health` 检查；
2. 每周一次本地 `/api/search` + 高风险规则题抽检；
3. 每周一次知识库行数与字段缺失统计；
4. 每周记录一次 Dify `8081` 是否恢复。

### 恢复 Dify 后

1. 每日一次 `/health` + Dify `8081` 连通性检查；
2. 每周一次 `20` 题或 `50` 题回归；
3. 每周一次平均耗时 / P95 / 失败率统计；
4. 每月形成一次试运行小结。

## 5. 启动长期运行前的前置条件

1. 恢复 `http://127.0.0.1:8081`；
2. 冻结并导入 3k 级正式数据集；
3. 完成一轮恢复后的回归评测；
4. 约定统一的记录口径与日志保存位置。

## 6. 说明

7×24 小时服务和 3 个月试运行只能基于真实时间积累，不能用一次性测试代替。本方案的目标，是让后续每一条长期指标都能留下真实可回放的证据。
