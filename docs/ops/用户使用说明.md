# 用户使用说明

> 项目：基于 Dify 的实验室安全小助手  
> 使用对象：学生、实验人员、实验室安全管理人员、项目演示人员  
> 页面地址：`http://127.0.0.1:8088`  

## 1. 系统用途

本系统用于辅助查询实验室安全相关问题，支持用户通过自然语言提出问题，并获得面向实验室安全场景的回答。

系统重点支持：

1. 实验室安全知识问答；
2. 危险化学品、设备操作、PPE、废弃物处置、应急流程等典型问题查询；
3. 答案引用依据展示；
4. 高风险问题安全提醒；
5. Dify 不可用时的结构化兜底回答；
6. 低置信问题记录，便于后续补充知识库。

本系统不替代实验室负责人、教师或学校正式安全管理流程。遇到紧急事故，应优先执行本单位应急预案并联系负责人。

---

## 2. 打开系统

启动系统后，在浏览器访问：

```text
http://127.0.0.1:8088
```

页面主要包括三部分：

1. 顶部项目说明和运行状态；
2. 左侧/上方问题输入区；
3. 右侧/下方回答和引用结果区。

---

## 3. 查看运行状态

页面右侧的“运行状态”区域会显示：

| 状态项 | 含义 |
|---|---|
| 应用版本 | 当前项目版本 |
| 问答链路 | 当前是否配置 Dify |
| Dify API | 当前 Dify API 地址 |
| Dify Key | 是否配置应用密钥 |
| 知识库 | 当前知识库条目与导入口径 |
| 评测口径 | 当前申报/展示使用的测试口径 |

如果显示：

```text
Dify Key：未配置
```

说明当前处于结构化兜底模式，回答不代表真实 Dify 工作流输出。

如果显示：

```text
Dify Key：已配置
```

说明系统会优先调用 Dify 工作流。

---

## 4. 提问方式

在问题输入框中输入实验室安全相关问题，例如：

```text
实验室发生化学品泄漏时，第一步应该怎么做？
```

或者：

```text
使用强酸时需要佩戴哪些个人防护用品？
```

再点击：

```text
发送到 Dify/RAG 链路
```

系统会执行：

1. 本地知识库检索；
2. 本地安全规则匹配；
3. 如命中强制安全规则，优先返回规则回答；
4. 如未触发强制规则，调用 Dify 工作流；
5. 如果 Dify 不可用，返回结构化兜底回答；
6. 展示回答和引用依据。

---

## 5. 理解回答区域

回答区域通常会显示：

```text
[decision | model]

回答正文
```

其中：

| 字段 | 说明 |
|---|---|
| `decision` | 系统决策类型 |
| `model` | 回答来源或模型类型 |

常见 `decision`：

| decision | 含义 |
|---|---|
| `dify_answer` | Dify 正常回答 |
| `dify_answer_guarded` | 命中安全规则后仍调用 Dify 回答 |
| `dify_low_confidence` | 知识库命中较弱，回答置信度较低 |
| `rule_blocked` | 高风险问题被规则拒答 |
| `emergency_redirect` | 问题被识别为应急场景，返回应急引导 |
| `need_more_info` | 信息不足，需要用户补充 |
| `structured_fallback` | Dify 不可用，使用结构化兜底回答 |

常见 `model`：

| model | 含义 |
|---|---|
| `dify-workflow` | Dify 工作流返回 |
| `rule-engine` | 本地规则直接回答 |
| `fallback-rule-engine` | Dify 不可用时的结构化兜底 |

---

## 6. 查看引用依据

页面下方“引用 / 检索结果”区域会显示本地知识库命中的条目。

每条引用包括：

1. 知识条目 ID；
2. 标题；
3. 匹配分数；
4. 风险等级；
5. 来源标题；
6. 摘要片段。

引用的作用：

- 帮助用户判断回答依据；
- 帮助项目人员检查知识库命中质量；
- 帮助后续补充或修正知识库。

如果引用为空或分数较低，说明当前问题可能不在知识库覆盖范围内，需要后续补充。

---

## 7. 只检索知识库

如果只想查看本地知识库命中情况，不调用 Dify，可以点击：

```text
只检索本地知识库
```

该功能适用于：

1. 检查某类问题是否已有知识条目；
2. 查看 Top-K 命中是否合理；
3. 调试知识库质量；
4. 在 Dify 不可用时快速查看依据。

## 8. 高风险问题处理说明

对于涉及危险操作、事故、泄漏、起火、暴露等问题，系统可能不会直接给出自由生成回答，而是返回安全规则引导。

示例问题：

```text
实验室发生化学品泄漏怎么办？
```

可能返回：

```text
结论：
若发生化学品泄漏：隔离现场、避免接触和吸入，在安全前提下通风并使用泄漏应急物资处理，立即报告实验室管理人员。

步骤：
1. 立即停止当前操作并隔离危险源。
2. 第一时间通知实验室负责人和安全联系人。
3. 按本单位 SOP 执行现场控制、上报和记录。

禁止事项：
- 禁止继续开展当前高风险操作。
- 禁止绕过通风、审批、联锁或 PPE 要求。
```

这属于预期行为，目的是避免系统输出不安全操作建议。

---

## 9. 低置信提示说明

当系统认为知识库命中不足时，回答末尾可能出现：

```text
附注：该问题已加入低置信待补强队列，后续会继续完善知识库。
```

这表示：

1. 当前问题没有找到足够强的知识库依据；
2. 系统仍尝试给出保守回答；
3. 该问题会被记录，后续用于补充知识库。

低置信记录位置：

```text
artifacts/low_confidence_followups/data_gap_queue.csv
```

## 11. 使用注意事项

1. 系统回答仅作为实验室安全学习和辅助查询参考；
2. 涉及具体实验操作时，应以本单位 SOP、教师指导和实验室负责人要求为准；
3. 遇到人员受伤、起火、泄漏、暴露等紧急情况，应立即执行应急预案；
4. 对高风险操作，不应仅凭系统回答开展实验；
5. 如发现回答不准确，应记录问题并反馈给项目维护人员；
6. 如页面显示 Dify 未配置，说明当前不是正式 Dify 工作流回答。

## 12. 常见问题

### 12.1 为什么有时没有调用 Dify？

可能原因：

1. `.env.dify_rag` 没有配置 `DIFY_APP_API_KEY`；
2. Dify 服务未启动；
3. Dify Base URL 配置错误；
4. Dify App Key 失效；
5. 问题命中了高风险本地规则，系统优先返回规则回答。

### 12.2 为什么回答显示 `structured_fallback`？

这表示 Dify 没有成功返回答案，系统启用了结构化兜底。应检查 Dify 配置和日志。

### 12.3 为什么有些问题直接被拒绝或应急引导？

因为问题可能涉及危险操作、违规处置或紧急事故。系统会优先遵循安全规则，而不是自由生成操作建议。

### 12.4 为什么引用和 Dify 回答可能不完全一致？

当前页面引用来自本地知识库检索，用于辅助展示依据；Dify 工作流内部也可能使用自己的 Dataset 检索。正式验收时，应确保 Dify Dataset 与本地导入包保持一致。

### 12.5 如何反馈问题？

可以记录：

1. 用户原始问题；
2. 系统回答；
3. 引用条目；
4. 是否低置信；
5. 期望补充的知识来源。

后续可将问题整理到知识库补强队列。

## 13. 演示建议

正式演示时建议按以下顺序：

1. 打开首页，展示项目定位和运行状态；
2. 展示 Dify Key 已配置；
3. 提问一个常规安全问题，展示 Dify/RAG 回答；
4. 展示引用依据；
5. 提问一个高风险问题，展示安全规则拦截或应急引导；
6. 点击“只检索本地知识库”，展示知识库命中；
7. 说明低置信问题如何进入补强队列。
