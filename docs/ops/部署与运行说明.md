# 部署与运行说明

> 项目：基于 Dify 的实验室安全小助手  
> 项目路径：`D:\newwork\lab-safe-assistant-dify-rag`  
> 适用系统：Windows / PowerShell  
> 默认端口：`8088`  

## 1. 运行目标

本说明用于启动第一个项目的最小演示系统。系统启动后提供：

1. Web 页面：`http://127.0.0.1:8088`；
2. 健康检查：`http://127.0.0.1:8088/health`；
3. 元信息接口：`http://127.0.0.1:8088/api/meta`；
4. 实验室安全问答接口：`POST /api/chat`；
5. 本地知识库检索接口：`GET /api/search`；
6. Dify 代理接口：`/v1/parameters` 和 `/v1/chat-messages`。

正式主链路是 Dify RAG 工作流；Dify 未配置或不可用时，系统会进入结构化兜底模式。

## 4. 配置环境变量

首次运行前，复制模板：

```powershell
Copy-Item .env.dify_rag.example .env.dify_rag
notepad .env.dify_rag
```

推荐配置：

```env
DIFY_BASE_URL=http://127.0.0.1:8081
DIFY_APP_API_KEY=app-xxxxxxxxxxxxxxxx
DIFY_TIMEOUT=120

DEMO_PORT=8088
DEFAULT_TOP_K=4
LOW_CONFIDENCE_TOP_SCORE=3.5
KB_IMPORT_SUCCESS_COUNT=398

ENABLE_EMBEDDING=0
SEMANTIC_WEIGHT=12.0
```

字段说明：

| 字段 | 说明 |
|---|---|
| `DIFY_BASE_URL` | Dify 服务地址，脚本会自动补 `/v1` |
| `DIFY_APP_API_KEY` | Dify 应用 API Key，形如 `app-...` |
| `DIFY_TIMEOUT` | Dify 请求超时时间，单位秒 |
| `DEMO_PORT` | 本地演示端口 |
| `DEFAULT_TOP_K` | 本地知识库引用数量 |
| `LOW_CONFIDENCE_TOP_SCORE` | 低置信判断阈值 |
| `KB_IMPORT_SUCCESS_COUNT` | 当前申报/展示口径中的导入条数 |
| `ENABLE_EMBEDDING` | 是否启用本地 embedding 检索 |
| `SEMANTIC_WEIGHT` | 语义检索加权参数 |

## 5. 启动系统

执行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/start_dify_rag_local.ps1
```

启动成功后会输出类似：

```text
[OK] Dify RAG app started
URL       : http://127.0.0.1:8088
Health    : http://127.0.0.1:8088/health
Dify key  : configured
Runtime   : D:\newwork\lab-safe-assistant-dify-rag\artifacts\local-dify-rag\runtime.json
Log       : D:\newwork\lab-safe-assistant-dify-rag\logs\dify_rag.log
Err Log   : D:\newwork\lab-safe-assistant-dify-rag\logs\dify_rag.err.log
```

如果 `DIFY_APP_API_KEY` 未配置，会显示：

```text
Dify key  : missing/fallback
```

此时系统仍可运行，但 `/api/chat` 会使用结构化兜底，不代表真实 Dify 工作流已验证通过。

## 8. 接口验证

### 8.1 健康检查

```powershell
Invoke-RestMethod "http://127.0.0.1:8088/health"
```

期望返回：

```json
{"status":"ok"}
```

### 8.2 元信息

```powershell
Invoke-RestMethod "http://127.0.0.1:8088/api/meta"
```

重点检查：

- `dify_app_key_configured`
- `dify_base_url`
- `knowledge_base_rows`
- `knowledge_base_imported`

### 8.3 本地知识库检索

```powershell
Invoke-RestMethod "http://127.0.0.1:8088/api/search?q=化学品泄漏&top_k=5"
```

期望返回：

- `count > 0`
- `citations` 包含知识条目。

### 8.4 实验室安全问答

```powershell
Invoke-RestMethod `
  -Uri "http://127.0.0.1:8088/api/chat" `
  -Method Post `
  -ContentType "application/json" `
  -Body '{"question":"实验室发生化学品泄漏时，第一步应该怎么做？"}'
```

如果真实 Dify 配置成功，建议检查：

- `model` 是否为 `dify-workflow`；
- `decision` 是否为 `dify_answer` 或 `dify_answer_guarded`；
- `answer` 是否为 Dify 返回内容；
- `citations` 是否有本地引用。

如果命中安全规则，`decision` 可能为：

- `rule_blocked`
- `emergency_redirect`
- `need_more_info`

这属于预期行为。

## 12. 常见问题

### 12.1 端口被占用

报错示例：

```text
Port 8088 is already occupied
```

处理：

1. 先执行停止脚本；
2. 或修改 `.env.dify_rag` 中的 `DEMO_PORT`。

```powershell
powershell -ExecutionPolicy Bypass -File scripts/stop_dify_rag_local.ps1
```

### 12.2 Dify Key 未配置

表现：

- `/api/meta` 中 `dify_app_key_configured=false`；
- 页面显示“Dify 未配置，当前处于结构化回退模式”；
- `/api/chat` 返回 `model=fallback-rule-engine`。

处理：

编辑 `.env.dify_rag`，填写：

```env
DIFY_APP_API_KEY=app-xxxxxxxxxxxxxxxx
```

然后重启。

### 12.3 Dify 地址错误

表现：

- 请求超时；
- `dify_request_failed`；
- `dify_proxy_request_failed`。

处理：

1. 确认 Dify 是否运行；
2. 确认 `DIFY_BASE_URL` 是否正确；
3. 浏览器访问 `http://127.0.0.1:8081` 或对应地址；
4. 检查 Dify App API 是否启用。

### 12.4 回答为空

表现：

```text
dify_empty_answer
```

处理：

1. 检查 Dify 工作流是否正确发布；
2. 检查工作流输出变量是否绑定到 answer；
3. 检查知识库是否关联到应用；
4. 检查模型供应商配置是否可用。

### 12.5 本地检索没有命中

处理：

1. 检查 `knowledge_base_curated.csv` 是否存在；
2. 执行 `/api/search` 单独测试；
3. 检查问题关键词是否覆盖知识库内容；
4. 将低置信问题加入后续知识库补强。

第一个项目建议按以下标准验收：

1. 页面可打开；
2. Dify Key 已配置；
3. Dify 工作流可返回回答；
4. 本地知识库可返回引用；
5. 高风险问题可触发安全规则；
6. 低置信问题可记录到补强队列；
7. Dify 导入报告已生成；
8. 最小测试报告已生成；
9. 申报书标准课题版已成稿。
