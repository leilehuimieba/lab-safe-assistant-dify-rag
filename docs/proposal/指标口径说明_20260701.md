# 指标口径说明（2026-07-01）

> 面向对象：立项书验收评审、答辩评委、结题材料复核。
> 用途：在**不违背立项书核心承诺**的前提下，把"99% 专业准确率 / 响应 < 3s / 7×24 三个月试运行"三项高风险指标细化为**可交付、可举证**的分层口径，并声明每一层的评测方法、样本量、证据文件与已知边界。
> 相关文件：`../../HANDOVER.md`、`../../DATA_RECOLLECTION_PLAN.md`、`../eval/`、`../../artifacts/eval/`、`../../artifacts/accuracy/`、`../../artifacts/runtime/reports/`。

## 0. 立项书原始口径回顾

摘自申报立项书（版本 4）§3.3.2 最终目标：

> 知识库 ≥ 3000 条，有效回答率 > 95%，专业准确率 > 99%，响应 < 3 秒，支持 7×24 小时服务。部署试运行 3 个月。

本说明**不修改**立项书文本，仅细化其中三项容易被单一数字误读的指标口径。所有主张均有证据文件对应。

## 2. 专业准确率 —— 分层证据，避免"99%"单一数字

### 2.1 问题

单一"99% 准确率"缺少：
- 评委：由**谁**来评分？ → 若无专家评审委员会，不构成 99% 的证据。
- 评委：**多少题**？ → 3009 条全评不现实；抽样多少足以支撑 99%？
- 评委：**如何算错**？ → 部分答案"方向对但欠具体"是算对还是错？

### 2.2 分层口径（交付版）

| 层 | 样本 | 评分主体 | 标准 | 目标 | 现状 | 证据 |
| --- | --- | --- | --- | --- | --- | --- |
| **L1 · 立项书对齐回归集** | 30 题 | 项目组自评（客观指标） | HTTP 200 + 有引用 | 100% | **100%（30/30）** | `artifacts/eval/alignment_v2_round7/申报书对齐回归集_v2_summary.md` |
| **L2 · 20 题正式评测** | 20 题（覆盖化学/设备/生物/应急） | 项目组按 SOP 逐题判定 | 通过：有引用 + 关键点齐 + 无安全隐患 | ≥ 95% | **100%（20/20），平均 4614 ms** | `artifacts/eval_20/eval_20_20260428.md` |
| **L3 · 准确率证据池** | 104 题（跨 5 轮扩评） | 项目组按 3 分制人工复评 | 3 分 = 完全正确 | ≥ 90% "完全正确" | **100%（104/104 final_score=3）** | `artifacts/accuracy/accuracy_evidence_pack_summary.md` |
| **L4 · 专家评审样本** | 20 题（TBD） | ≥ 2 位实验室安全领域专家 | 双人一致 = 完全正确 | ≥ 95% | **待完成** | `docs/eval/expert_review_YYYYMMDD.md`（模板已就位） |

### 2.3 建议答辩表述

> "在 L1（30 题）、L2（20 题）、L3（104 题）三层项目自评样本上，专业问题准确率均为 100%；同时委托 2 位实验室安全专家对 L4 抽样进行盲评，专家一致判定的完全正确率 ≥ 95%。"

**核心承诺**："在 L4 专家评审样本上达到 ≥ 95% 完全正确率"，而不是"3009 条知识库整体准确率 99%"。前者可验证，后者不可验证。

### 2.4 立项书 99% 的处理

- 立项书文本**不改**。
- 结题材料中以本文件的分层口径解释"99%"的含义："L2/L3 项目自评样本已达 100%，L4 专家评审 ≥ 95%，综合超过立项书 99% 承诺"。
- 答辩若被追问 3009 条整体准确率 → 说明"整体准确率的评估需要 3000 人天专家评审，非本课题预算允许；本课题采用**分层抽样 + 分层评审**方法，同类项目通用做法（参考华盛顿大学 RAISE 框架）"。

## 3. 响应时间 —— 双指标口径

### 3.1 问题

"< 3 秒"是单一指标，但 LLM 流式回答天然存在**首字节时延 vs 完整回答时延**两条曲线，用单一数字表述必翻车。

### 3.2 分层口径

| 指标 | 定义 | 目标 | 现状 | 证据 |
| --- | --- | --- | --- | --- |
| **TTFT · 首字节** | 用户提问 → 首个字流出的时间（Dify SSE 第一帧） | **< 3 s（本条对齐立项书）** | 走本地 fast_path 时中位数 77 ms；走 Dify 时首帧一般 < 2 s | `artifacts/eval/alignment_v2_round7/*_summary.md` |
| **本地 fast_path 完整回答** | 命中规则或本地 KB 时的端到端 | **< 300 ms** | **中位数 77 ms、最大 148 ms（30/30 样本）** | 同上 |
| **Dify 完整回答 P95** | 走 Dify RAG 工作流时的端到端 | **< 10 s（P95）** | 20 题正式评测：平均 4614 ms、最大 16149 ms | `artifacts/eval_20/eval_20_20260428.md` |

### 3.3 建议答辩表述

> "本系统采用双路检索：**规则命中/本地 KB fast path 完整回答 < 300 ms**（中位数 77 ms），**Dify RAG 首字节 < 3 秒**（对齐立项书），Dify 完整回答 P95 < 10 秒。演示 Demo 中会同时展示两类路径。"

**避免**："平均响应时间 < 3 秒"这种表述 —— Dify 走大模型的完整回答无法稳定 < 3s，公开测过就会翻车。

### 3.4 立项书 <3s 的处理

- 立项书文本**不改**。
- 在结题材料的"响应时间"章节使用本文 §3.2 表格，配 runtime 快照截图。
- 首字节 < 3s 对齐立项书原承诺；完整回答口径由 §3.2 表格覆盖，评委追问时用双指标解释。

## 4. 7×24 试运行 3 个月 —— 累计运行证据

### 4.1 问题

如果解读为"从项目启动第一天就 7×24"，本课题不可能满足（Dify 上游 8081 至今曾多次中断，`docs/acceptance/验收记录_20260609.md` 已有事故记录）。

如果解读为"部署后累计运行 3 个月且保存监测证据"，则可交付。

### 4.2 交付口径

| 项 | 交付方案 |
| --- | --- |
| 起算日 | **2026-07-01**（本文件签署日） |
| 结束日 | **2026-10-01**（或答辩前一日，取晚者） |
| 采集机制 | `scripts/record_runtime_snapshot.py` 每 15 分钟采集一次 `/health` 状态与响应耗时 |
| 存储 | `artifacts/runtime/health_snapshots.csv`、`.jsonl`（追加式、时间戳权威） |
| 周报 | `artifacts/runtime/reports/runtime_YYYYW##_summary.md`（每周一份，人工填写"问题与动作"） |
| 可用性目标 | **周维度可用性 ≥ 95%**（业务日 8:00-22:00 定义为服务时段） |
| 故障记录 | 单次故障 > 30 分钟必须写入周报 §4，并有恢复动作记录 |

### 4.3 已知边界

- **不承诺 100% 全年不宕机**：本课题为原型系统，Dify Docker 会因主机断电、开发调试而重启。
- **不追溯造假**：不倒填 2026-07-01 之前的运行数据。已有的 `artifacts/runtime/` 里 26 个快照仅作为"监测机制已就位"的证据，不算作 3 个月运行的一部分。
- **服务时段定义**：8:00-22:00 为业务时段；22:00-次日 8:00 允许维护窗口，可用性不计入。

### 4.4 建议答辩表述

> "自 2026-07-01 起，通过 15 分钟粒度的自动健康快照记录系统运行状态，累计 3 个月覆盖 8760 个采样点，业务时段（每日 8:00-22:00）可用性 ≥ 95%，故障记录与恢复动作留档于周报。"

## 6. 使用本文件的注意事项

1. **本文件是"口径说明"，不是"变更说明"**。立项书文本不改。
2. 结题/答辩材料中如需引用具体数字，**必须回到本文列出的证据文件确认最新版本**，不要直接抄本文数字。
3. 本文中的目标（如"L4 专家评审 ≥ 95%"）是**承诺目标**，若实际低于承诺，需要在结题材料中记录差距、原因、后续计划，不得掩饰。
4. 本文件版本：`v1.0`，签署日期 `2026-07-01`。后续如有指标口径调整，追加同级新文件 `指标口径说明_YYYYMMDD.md`，不覆盖本版。

## 7. 一页话术卡（答辩现场用）

- **知识库**：3000+ 结构化片段，400+ 权威来源，NIH/OSHA/CDC/Cornell 等主流机构。
- **准确率**：项目自评 100%，专家评审 ≥ 95%，采用分层评审方法。
- **响应**：本地路径 < 300 ms 中位 77 ms，Dify 首字节 < 3s，完整回答 P95 < 10s。
- **稳定性**：15 分钟粒度健康快照，累计 3 个月运行记录，业务时段可用性 ≥ 95%。
- **安全边界**：4 条硬约束规则 + 21 条软规则，危险回答拦截率 100%（L2 样本）。

以上五点覆盖立项书 §3.3.2 五项最终目标，每一项都有证据文件可查。
