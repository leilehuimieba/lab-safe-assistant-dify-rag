# 三、课题设计论证

## 1. 研究意义

### 1.1 研究背景

高校实验室是教学科研活动的重要载体，同时也是化学品、仪器设备、电气系统、废弃物和应急处置等安全风险相对集中的场所。实验室安全管理涉及制度规范、操作规程、危险化学品安全说明、个体防护、废弃物处置和事故应急等多类知识。传统管理方式通常依赖纸质制度、人工培训和经验传递，存在资料分散、查询效率低、更新不及时、学生理解不一致等问题。

随着大语言模型和智能体平台的发展，将实验室安全知识库与大模型问答能力结合，能够为学生和实验人员提供更加便捷的安全知识查询方式。但通用大模型如果缺少领域知识约束，容易出现回答依据不清、内容不稳定或对高风险问题回答不够保守等问题。因此，有必要探索一种面向实验室安全场景的检索增强问答方案，通过知识库检索、来源追溯和安全规则约束，提高问答的可靠性和实用性。

Dify 平台提供知识库管理、工作流编排和应用 API 调用能力，适合快速搭建面向具体领域的 RAG 应用。本课题拟基于 Dify 搭建实验室安全小助手系统，将实验室安全资料整理为结构化知识条目，导入 Dify 知识库，并结合本地安全规则和演示页面，形成可运行、可测试、可继续扩展的实验室安全问答原型。

### 1.2 应用价值

本课题具有以下应用价值：

1. 提升实验室安全知识查询效率。学生和实验人员可以通过自然语言直接提问，减少在制度文件、SOP 和安全手册中反复查找的时间。
2. 增强安全知识学习的及时性。系统可围绕危化品、设备操作、PPE、废弃物处置和应急流程等典型场景提供即时辅助。
3. 提高回答可追溯性。通过知识库引用展示，用户可以了解回答依据，便于进一步核对来源材料。
4. 降低高风险问题回答风险。系统对危险操作、违规处置和应急事故类问题设置规则约束，避免直接输出不安全建议。
5. 为后续实验室安全智能化建设提供基础。项目形成的数据结构、导入流程和问答接口可作为后续开展更完整实验室安全服务的基础。

### 1.3 技术价值

本课题的技术价值主要体现在：

1. 探索 Dify 平台在高校实验室安全场景中的轻量化落地方式；
2. 构建适合实验室安全问答的结构化知识库字段体系；
3. 将 RAG 问答与本地安全规则结合，提高系统在高风险场景下的可控性；
4. 建立低置信问题记录机制，为后续知识库持续补强提供依据；
5. 形成一套可复用的“资料整理—知识库导入—Dify 工作流—问答测试”技术路径。

## 2. 国内外研究与应用现状

### 2.1 实验室安全数字化管理现状

目前高校实验室安全管理已逐步从纸质制度和线下培训向数字化平台转变。常见做法包括线上安全考试、实验室准入系统、危化品台账、设备预约管理和隐患上报系统等。这些系统在规范管理流程方面发挥了积极作用，但多数系统仍以流程管理和信息登记为主，对自然语言问答、知识检索和即时辅助支持不足。

### 2.2 大语言模型与 RAG 应用现状

大语言模型具备较强的语言理解和生成能力，可用于问答、摘要、解释和辅助决策等任务。但在专业领域直接使用通用模型，容易存在事实不准确、依据不明确和输出不可控等问题。RAG 技术通过在生成回答前检索外部知识，将领域资料作为上下文提供给模型，有助于提升回答的准确性和可追溯性。

Dify 等智能体平台降低了 RAG 应用搭建门槛，提供知识库管理、工作流编排、模型调用和 API 发布等能力，适合课题原型开发和小范围验证。

### 2.3 现有方案不足

现有实验室安全信息化系统和智能问答方案仍存在以下不足：

1. 知识资料分散，缺乏统一结构化整理；
2. 问答系统与实验室安全制度、SOP 和应急流程结合不够紧密；
3. 回答缺少来源追溯，难以判断依据是否可靠；
4. 对高风险问题缺少稳定的拒答、保守回答和应急引导机制；
5. 知识库更新和低置信问题补强机制不完善。

本课题拟针对上述不足，构建面向实验室安全场景的 Dify RAG 问答原型。

## 3. 课题研究内容

### 3.1 实验室安全知识库建设

围绕高校实验室安全典型问题，整理制度规范、SOP、MSDS、设备操作要求、PPE 要求、废弃物处置和应急流程等资料，形成结构化知识库。知识条目包含标题、类别、风险等级、典型问题、标准回答、操作步骤、PPE、禁止事项、应急处置、来源标题、来源机构、来源链接和标签等字段。

阶段目标为形成不少于 300—500 条可导入 Dify 的高质量知识条目，并建立可持续扩展的数据模板。当前项目已形成本地知识库和 Dify 导入包，后续将结合导入结果和测试反馈持续补强。

### 3.2 基于 Dify 的 RAG 问答应用搭建

利用 Dify 平台创建实验室安全知识库和问答应用，将整理后的知识条目导入 Dify Dataset，并配置知识检索和大模型回答工作流。用户通过本地 Web 页面或接口提交问题，系统调用 Dify 应用 API，获得基于知识库增强的回答。

### 3.3 本地 Web 演示与接口服务

构建 FastAPI 本地服务，提供最小可运行演示系统。主要接口包括：

1. `/health`：健康检查；
2. `/api/meta`：系统元信息；
3. `/api/search`：本地知识库检索；
4. `/api/chat`：实验室安全问答；
5. `/v1/parameters`、`/v1/chat-messages`：Dify 代理接口。

本地页面用于展示系统状态、问题输入、回答内容和知识库引用。

### 3.4 高风险问题安全规则约束

针对危险操作、违规处置、事故应急等问题，建立本地安全规则库。系统在调用 Dify 前先进行规则匹配，若问题涉及高风险终止动作，则优先返回规则回答或应急引导，避免大模型输出不当操作建议。

规则动作包括：拒答、应急引导、要求补充信息和安全提示。规则回答统一包含结论、步骤、禁止事项、应急升级和参考依据。

### 3.5 低置信问题补强机制

当本地知识库检索无命中或命中分数较低时，系统将问题记录到低置信补强队列。后续可根据该队列补充知识条目、重写问题或完善来源材料，从而形成知识库持续优化机制。

### 3.6 测试与评估

建立基础评测流程，使用评测集对问答可用性、引用返回、高风险合规响应和系统稳定性进行测试。评测结果将形成测试报告，为课题验收和后续优化提供依据。

## 4. 拟解决的关键问题

### 4.1 实验室安全资料分散、查询效率低

通过结构化整理实验室安全资料，并导入 Dify 知识库，使用户能够通过自然语言快速查询安全知识。

### 4.2 通用大模型回答缺乏领域依据

通过 RAG 技术将实验室安全知识库作为回答依据，并在页面展示本地知识库引用，增强回答可追溯性。

### 4.3 高风险问题回答不可控

通过本地规则库对危险操作、应急事故和违规处置问题进行前置判断，必要时直接返回保守回答或应急引导。

### 4.4 知识库覆盖不足和低置信问题难以沉淀

通过低置信问题队列记录未被知识库充分覆盖的问题，为后续补充知识库提供依据。

### 4.5 原型系统需要便于部署和演示

通过 FastAPI、PowerShell 启停脚本和简化 Web 页面，实现本地可运行、可展示、可测试的原型系统。

## 5. 技术路线

本课题采用如下技术路线：

```text
实验室安全资料收集
→ 资料清洗与结构化整理
→ 知识库 CSV 标准化
→ Dify Dataset 导入与索引
→ Dify RAG 问答工作流配置
→ FastAPI 代理与本地展示页面
→ 本地安全规则校验与结构化兜底
→ 答案生成、引用展示与低置信记录
→ 测试集评测与持续优化
```

具体步骤如下：

1. 收集实验室安全制度、SOP、MSDS、设备说明和应急流程等资料；
2. 按统一字段整理为知识条目，形成 CSV 数据包；
3. 将知识库导入 Dify Dataset，并配置知识检索参数；
4. 创建 Dify 问答应用或工作流，使用户问题能够结合知识库生成回答；
5. 通过 FastAPI 封装 `/api/chat` 和 `/api/search` 等接口；
6. 在本地页面展示回答和引用；
7. 在回答前进行安全规则判断，对高风险问题进行保守响应；
8. 使用测试集评估回答有效性和安全合规性；
9. 将低置信问题记录到补强队列，持续完善知识库。

## 6. 研究方法

### 6.1 文档整理法

收集实验室安全相关资料，对制度文件、SOP、MSDS、设备说明和应急流程进行分类整理，提取典型问题、标准回答和安全要点。

### 6.2 原型开发法

基于 Dify 平台和 FastAPI 开发原型系统，快速验证 Dify 知识库问答、本地规则约束和页面展示的可行性。

### 6.3 测试评估法

构建测试问题集，对常规问答、危化品问题、PPE 问题、废弃物处置、应急问题和违规操作问题进行测试，评估系统有效性。

### 6.4 迭代优化法

根据低置信问题、测试失败样例和用户反馈，对知识库内容、规则配置和 Dify 工作流进行迭代优化。

## 7. 创新点

### 7.1 面向实验室安全场景的 Dify RAG 问答原型

本课题将 Dify 平台、实验室安全知识库和 RAG 问答流程结合，面向高校实验室安全问题构建轻量化问答原型。

### 7.2 知识库引用与来源追溯机制

知识条目保留来源标题、来源机构和来源链接，系统在本地检索结果中展示引用依据，提高回答可信度。

### 7.3 大模型问答与安全规则协同

针对高风险问题，本课题不完全依赖模型自由生成，而是引入本地安全规则，实现拒答、应急引导和补充信息提示。

### 7.4 低置信问题补强机制

系统可将知识库命中不足的问题记录到补强队列，为后续知识库持续完善提供数据依据。

### 7.5 低成本、可复制的实验室安全智能问答路径

项目采用 Dify、FastAPI、CSV 知识库和本地脚本组合，部署门槛较低，便于在类似实验室安全知识服务场景中复用。

## 2. 技术可行性

从技术实现上看，本课题采用成熟工具和轻量化架构，具备较高可行性：

1. Dify 平台已提供知识库管理、RAG 工作流和应用 API 能力，可减少底层模型服务开发成本；
2. FastAPI 可快速构建本地接口服务，便于与 Dify API 对接；
3. CSV 知识库格式简单清晰，便于人工审核、批量导入和后续维护；
4. 本地规则库采用 YAML 文件维护，便于新增和调整高风险规则；
5. PowerShell 脚本可在 Windows 环境下完成启动、停止和状态查看；
6. Dify 不可用时保留结构化兜底，有利于提升演示稳定性。

## 3. 资料可行性

实验室安全资料来源较为明确，包括学校实验室安全制度、实验室 SOP、MSDS、设备操作说明、安全培训资料和公开实验室安全指南等。这些资料可整理为结构化知识条目，用于 Dify 知识库导入。

当前项目已形成阶段性知识库和导入包，后续可根据测试结果和低置信问题队列继续补充。

## 4. 时间可行性

本课题目标聚焦于 Dify + RAG 问答原型，不扩展为完整实验室安全管理平台，因此开发范围可控。项目可以分阶段完成：

1. 前期整理知识库和技术路线；
2. 中期完成 Dify 导入与问答链路；
3. 后期完成测试评估和文档归档。

在已有代码和数据基础上，后续工作主要集中在 Dify 真实配置、导入报告、测试报告和申报书成稿，具备按期完成条件。

本项目采用 Dify 平台、开源 Web 框架和结构化 CSV 知识库，整体经费需求较低。经费主要用于资料整理、模型或平台调用、计算资源使用、文档印刷和测试材料整理，不涉及大型硬件采购。

| 经费项 | 建议用途 |

| 资料费 | 安全规范、SOP、MSDS 和培训资料整理 |
